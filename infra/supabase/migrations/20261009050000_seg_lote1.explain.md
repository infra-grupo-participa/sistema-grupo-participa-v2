## Por que
Inventário de 08/10: 100+ funções SECURITY DEFINER executáveis por `anon` nos schemas expostos. Entre elas
`sip.close_ciclo` e `sip.fn_recomecar_ciclo`, que alteram o ciclo de qualquer aluno sem login e sem guarda.

## Como se escolheu o que fechar (só o que ninguém chama sem login)
1. Catálogo: funções DEFINER com EXECUTE para anon e USAGE no schema; excluídas as citadas em policy, view,
   default de coluna ou corpo de outra função (anon precisa delas para ler).
2. Código: grep nos repositórios locais (Projetos, Downloads, OneDrive). Os chamadores do SIP usam service_role
   (`sip-thb/src/server/db.ts:26`, edges `sip-auth`, `sip-api`, `ig-collect`); o login do SIP é JWT próprio.
3. Logs (edge_logs, 24 h — é a retenção disponível): `check_login_rate_limit`/`record_login_attempt` só aparecem com a chave secreta.
4. As funções públicas por desenho (token, segredo, formulários, plantão GPS, CNHF) ficaram de fora.
