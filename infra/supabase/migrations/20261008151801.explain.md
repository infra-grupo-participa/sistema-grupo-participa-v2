# 20261008151801: papel LEITOR no CRM (admin/dev fora do Comercial vê tudo, não escreve nada)

**STATUS: APLICADA em produção em 08/10/2026 às 15:18 UTC** (versão `20261008151801`, nome `crm_papel_leitor`,
escrita como `20261008lt`), pelo `apply_migration` do MCP. md5 dos statements gravados = md5 do arquivo antes da troca do
cabeçalho da linha 1 = `b9ccaf96b481674414b2b4ed0706759c`.

Decisão do Arthur (08/10/2026): admins do sistema que não são gestores nem vendedores do Comercial veem o CRM **só para
leitura**. Desde a 20261008150041 eles recebiam "Sem acesso ao Comercial.".

## ⚠️ Regra para toda RPC de escrita NOVA do CRM

**Toda RPC `crm_*` que escreve chama `crm.guarda_escrita()` (padrão: `v_r := crm.guarda_escrita(); if v_r is not null then
return v_r; end if;`) ou, se não usa a guarda, `if not crm.pode_escrever() then return crm.res(false, 'Acesso só de
leitura.'); end if;` logo depois do `begin`.** Sem isso o leitor escreve, porque `crm.eh_gestor()` (visão) é verdadeiro
para ele. Conferência rápida (precisa dar zero linhas):

```sql
select p.oid::regprocedure from pg_proc p join pg_namespace n on n.oid = p.pronamespace
 where n.nspname = 'public' and p.proname like 'crm\_%' and has_function_privilege('authenticated', p.oid, 'execute')
   and pg_get_functiondef(p.oid) ~* '\m(insert|update|delete)\M'
   and pg_get_functiondef(p.oid) !~ '(crm\.guarda_escrita\(\)|crm\.pode_escrever\(\))';
```
(Exceção conhecida: `crm_mcp_oauth_autorizar`/`crm_mcp_oauth_cliente`, que exigem `crm.mcp_papel(eu)` — nulo para o leitor.)

Agentes mexendo em paralelo hoje (MCP OAuth, WhatsApp por QR/Evolution, notas do funil de saldo) podem ter criado RPC de
escrita depois desta migration: rodar a conferência acima. Se `crm_mcp_criar_token`/`crm_mcp_revogar_token` forem
recriadas a partir de arquivo antigo, a linha `crm.pode_escrever()` some — recolocar.

## 2. Quem é leitor (medido depois de aplicar)

10 perfis: 6 `admin` + 4 `dev`. Dos 4 masters (`acesso.master`): 2 viraram leitores (1 admin, 1 dev); 1 é gestor
(admin, na lista); 1 é `visualizador` (conta de teste) e segue sem acesso — decidido pela regra de cargo, sem nome fixo.
Nenhum leitor tem `eh_gestor(uuid)`, `mcp_papel`, linha em `crm.distribuicao` ou em `crm.vendedor`.

Consequência a registrar: catalogação de origem (`crm.pode_catalogar()` = admin/dev ou `dados.catalogar`) passa a recusar
o leitor. Hoje nenhum perfil tem `dados.catalogar` e nenhuma regra foi gravada pela tela (`atualizado_por` vazio), mas o
dono da área de Dados é admin → leitor. Se ele precisar editar regras pela tela, é decisão de negócio (ex.: exceção por
`dados.catalogar` em `crm.pode_escrever`).

## 4. As 5 perguntas

Escala: `crm.eh_leitor(uuid)` = 1 linha de `perfis` por PK + `crm.config` + `eh_gestor(uuid)` + `vendedor_ativo` (PKs).
Índice: PKs. Frequência: `crm.eh_gestor()` roda em toda RPC/policy do CRM (initplan nas policies, 1×/consulta); o custo
a mais só existe para quem não é gestor (o `or` resolve no 1º termo para o gestor). Repetição: nenhuma nova. Reversão:
abaixo, sem deploy.

## 5. Como desligar / reverter

- Kill-switch (≈10 s, sem deploy): `update crm.config set leitor_ligado = false;` → ninguém é leitor, admins voltam ao
  42501 "Sem acesso ao Comercial." (o front mostra o erro de antes).
- Reverter de vez: `crm.eh_gestor()` → `select crm.eh_gestor((select auth.uid()));`; `crm.guarda_escrita()`, `crm_sessao`,
  `crm_estrategia_acesso` → corpos anteriores (md5 na guarda da migration); as trocas cirúrgicas estão literais no bloco
  `$t$` (colunas `antes`/`depois`) e no bloco `$w$` (linha injetada após o `begin`).
