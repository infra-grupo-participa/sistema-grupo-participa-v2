# 20261005n: Marketing > Mensageria, o banco da área (o que foi medido e o contrato)

**Status: APLICADA em produção em 05/10/2026** (`supabase_migrations.schema_migrations` versão `20261005230000`, via Management API, depois dos 3 blocos do ensaio em produção). Depende da 20261005m (já em produção: `mkt.projetos` com 4 linhas).
Quem aplicar roda antes os 3 blocos de `20261005n_ensaio.sql`. Cada bloco termina com um erro proposital que traz o
relatório: `ENSAIO 20261005n BLOCO n CONCLUÍDO`. Qualquer outro erro: não aplicar.

## O que entra

| Peça | O que é |
|---|---|
| `mkt_mensageria.disparos` | Log central: todo envio (API WhatsApp, e-mail, SMS, ligação, grupo) de qualquer ferramenta. Retorno e custo **sem default**: nulo = não lançado, 0 = medido e deu zero |
| `mkt_mensageria.numeros` | Números (E.164), responsável, finalidade, ferramenta, capacidade/dia, status (`status_desde` carimbado pelo trigger) |
| `mkt_mensageria.ferramentas` | 13 de seed (7 com API, 6 sem), custo mensal nulo. Nome único sem diferenciar maiúscula |
| `mkt_mensageria.importacoes` | Uma linha por planilha confirmada |
| `mkt_mensageria.historico` | Toda inserção/alteração/arquivamento nas 3 tabelas (trigger), linha inteira antes/depois, `por = auth.uid()` |
| Triggers | `a_carimbo` (criado/atualizado em/por), `b_status` (numeros), `b_procedencia` (disparos: `origem`, `origem_sistema`, `id_externo`, `importacao_id` imutáveis), `z_historico`, `sem_delete` + `sem_truncate` (as 5 tabelas) e `sem_update` (historico, importacoes): 42501 |
| `public.mkt_msg_*` (11) | O contrato abaixo. Todas SECURITY DEFINER, `search_path ''`, guarda `if not coalesce(mkt.pode_ver('mkt_mensageria'), false)` (42501); a de LGPD usa `coalesce(gp_is_admin(), false)` |

Projetos: a tela usa **`public.mkt_projetos_listar()`** (20261005m), que devolve `[{id, sigla, nome, ativo, …}]`.
Não existe `mkt_msg_projetos_listar`. A Mensageria grava e filtra projeto pela **sigla**.

## Contrato (o que o front consome)

Toda função de escrita devolve `{ok, msg, id?}`. `msg` é texto pronto para a tela, em português. `ok:false` não é
exceção: só falta de acesso vira erro (42501). Dinheiro sempre em **centavos** (inteiro). Instante em ISO com fuso.

**`mkt_msg_disparos_listar(p_de date, p_ate date, p_projeto text = null, p_canal text = null, p_ferramenta bigint = null)`**
Período obrigatório, inclusivo, no máximo 366 dias, em dias de São Paulo. `p_projeto` é a sigla. Não traz arquivados.
```
{ ok, de, ate, limite: 500, truncado: bool,            -- truncado = o período tem mais de 500 disparos
  linhas: [ { id, enviado_em, projeto_id, projeto (sigla), canal, ferramenta_id, ferramenta (nome), numero_id, numero,
              tipo, copy_texto, copy_link, publico_lista, publico_origem, tamanho_lista,
              entregues, lidas, cliques, falhas, custo_centavos,     -- null = não lançado
              disparado_por, retorno_em, origem, origem_sistema, id_externo, importacao_id, atualizado_em,
              pendencias: ["sem_custo" | "sem_retorno" | "conferir_zero_leitura"] } ],   -- até 500, enviado_em desc
  totais: { qtd, tamanho, entregues, lidas, cliques, falhas, custo_centavos, com_custo,
            sem_custo, sem_retorno, conferir_zero_leitura },          -- do período INTEIRO, não só das 500 linhas
  por_canal: [ { canal, qtd, tamanho, entregues, lidas, cliques, falhas, custo_centavos, sem_custo } ] }
```
Soma sem nenhum valor lançado vem `null` (não 0). Pendências: `sem_custo` = custo nulo; `sem_retorno` = entregues
**ou** lidas nulas; `conferir_zero_leitura` = lidas = 0 e custo > 0. Erro: `{ok:false, msg}` (período, projeto, canal).

**`mkt_msg_disparo_salvar(p jsonb)`**, sem `id` cria (origem `manual`), com `id` edita (arquivado não se edita).
Campos: `enviado_em` (`"2026-10-05T14:30"` = horário de SP, ou ISO com fuso), `projeto` (sigla), `canal`,
`ferramenta_id`, `numero_id?`, `tipo` (só em `whatsapp_api`, e lá obrigatório: `utility`/`marketing`), `copy_texto?`,
`copy_link?` (ao menos um), `publico_lista`, `publico_origem?`, `tamanho_lista`, `entregues?`, `lidas?`, `cliques?`,
`falhas?`, `custo_centavos?`, `disparado_por`. `origem_sistema`/`id_externo` no JSON são **ignorados** (a tela não
grava nem altera). Ferramenta desativada ou número arquivado: recusa com mensagem. Retorno `{ok, msg, id}`; com erro de
campo: `{ok:false, msg (o 1º), erros:[{campo, msg}]}`. Retorno/custo lançados na criação ou alterados na edição
carimbam `retorno_em`.

**`mkt_msg_disparo_arquivar(p_id bigint, p_motivo text)`**: motivo de 3 a 500 caracteres. Some da lista e dos totais;
fica no banco e no histórico. Não há "desarquivar" pela tela (ver Não feito).

**`mkt_msg_disparo_lancar_retorno(p_id bigint, p_entregues int, p_lidas int, p_cliques int, p_falhas int, p_custo_centavos int)`**
Os 5 valores substituem os atuais (nulo = não lançado). `retorno_em = now()`; se os 5 vierem nulos, volta a nulo.
Retorno `{ok, msg, id, pendencias}`. Chamada por nome no PostgREST: os parâmetros são esses (`p_…`).

**`mkt_msg_importar(p_linhas jsonb, p_confirmar bool = false, p_arquivo text = null, p_aceitar_duplicadas bool = false)`**, até 2.000 linhas.
Cada linha: `{data:"05/10/2026", hora:"14:30", projeto:"PB26", canal:"API WhatsApp"|"whatsapp_api"|"E-mail"|…,
ferramenta:"sendflow" (nome, sem diferenciar maiúscula), numero:"+55 11 9…" (vazio = sem número), tipo:"Utilidade"|
"utility"|"Marketing"|"", copy_texto, copy_link, publico_lista, publico_origem, tamanho_lista:"1.234", entregues,
lidas, cliques, falhas ("1.234" ou vazio), custo:"1.234,56" (reais; vazio = não lançado), disparado_por}`.
```
{ ok, msg, erros: [ {linha, campo, msg} ],   -- linha = posição no array (1 = primeiro item); até 500 erros
  erros_total, validas, total, duplicadas_banco: [linha, …], duplicadas_lote: [linha, …], importacao_id? }
```
`p_confirmar=false` só valida e lista as duas espécies de duplicata. `true` grava **tudo ou nada**: um erro em
qualquer linha = nada entra. Duplicata = mesma data/hora, projeto, canal e lista: `duplicadas_banco` (já no log, não
arquivada) e `duplicadas_lote` (todas as linhas de um grupo repetido na própria planilha). Com qualquer duplicata,
`true` **recusa** (`ok:false`, nada grava) a menos que `p_aceitar_duplicadas=true` ("importar mesmo assim").
A confirmação pega `pg_advisory_xact_lock`: duas confirmações simultâneas viram fila e a segunda vê a primeira.
A planilha **não grava** `origem_sistema`/`id_externo` (ignorados se vierem): a chave externa é só da API.

**`mkt_msg_numeros_listar()`** → `{ok, hoje, numeros:[{id, numero, projeto_id, projeto, frente, responsavel,
finalidade, ferramenta_id, ferramenta, capacidade_dia, status, status_desde, arquivado_em, consumo_hoje,
acima_da_capacidade, atualizado_em}]}`. `consumo_hoje` = soma de `tamanho_lista` dos disparos não arquivados do
número com `enviado_em` hoje (dia de SP). Vem do log; 0 = nada enviado hoje. Ordem: ativos primeiro, arquivados no fim.

**`mkt_msg_numero_salvar(p jsonb)`**: `numero` ("+55 (11) 90000-0001": espaço, traço e parêntese saem; `+` e país
obrigatórios), `projeto?` (sigla), `frente?`, `responsavel`, `finalidade`, `ferramenta_id?`, `capacidade_dia?` (1 a
1.000), `status`, `arquivado?` (bool). → `{ok, msg, id}`.

**`mkt_msg_ferramentas_listar()`** → `[{id, nome, api, custo_mensal_centavos, responsavel, ativa, obs, atualizado_em}]`
(array, como `mkt_projetos_listar`). **`mkt_msg_ferramenta_salvar(p jsonb)`**: `nome`, `api` (`sim`|`futura`|`nao`),
`custo_mensal_centavos?`, `responsavel?`, `ativa?`, `obs?` → `{ok, msg, id}`. Ferramenta não se apaga: `ativa=false`.

**`mkt_msg_historico(p_tabela text, p_id text)`** (`disparos`|`numeros`|`ferramentas`) → `{ok, itens:[{id, acao
(inserir|alterar|arquivar|anonimizar), em, por, por_nome, antes, depois}]}`, até 200, mais recente primeiro.

**`mkt_msg_anonimizar_disparo(p_id bigint, p_motivo text)`** (LGPD, **só admin/dev** via `gp_is_admin`, mesmo depois
que `mkt.pode_ver` abrir para operador/gestor) → `{ok, msg, id, historico_limpo}`. Troca `copy_texto`,
`publico_lista` e `publico_origem` por `[anonimizado]` no disparo **e em todas as linhas do histórico dele**, e grava
uma linha `anonimizar` com `depois = {campos, motivo, linhas_de_historico_limpas}` (sem o conteúdo). É a única
exceção ao bloqueio de UPDATE do histórico: flag `mkt_mensageria.anonimizar` local à transação, desligada antes de
sair; mesmo com ela ligada, o trigger só deixa mudar `antes`/`depois` (id, tabela, registro, ação, autor, data fixos).

## Acesso: onde entra o setor `mkt_mensageria`

Hoje `mkt.pode_ver(p_area)` (20261005m) devolve `gp_is_admin()` e ignora a área: só admin/dev. **Não foi alterada.**
Quando o dono liberar operador/gestor, a mudança é **só** nessa função, com a mesma assinatura (`create or replace`
com a mesma assinatura não cria sobrecarga), por exemplo:
```sql
select coalesce(public.gp_is_admin(), false)
    or (p_area = 'mkt_mensageria' and exists (
          select 1 from public.perfis p
           where p.id = (select auth.uid()) and p.status = 'ativo' and p.cargo in ('gestor', 'operador')
             and 'mkt_mensageria' = any(p.areas)));      -- conferir o nome da coluna de áreas antes
```
As 10 funções da área já passam `'mkt_mensageria'`; nada muda nelas (a de LGPD continua só admin). No front, a mesma regra em
`web/app/(admin)/marketing/layout.tsx` (hoje redireciona quem não é admin/dev).

## Não feito

- **Desarquivar disparo pela tela**: não existe função. Disparo arquivado só volta por SQL do dono (número desarquiva normalmente).
- **Concorrência de duas confirmações de importação**: o `pg_advisory_xact_lock` está no código, mas não foi testado com duas conexões.

## Não verificado

- Payload com copy real: o ensaio usa copy curta. Com `copy_texto` de 4.000 caracteres, 500 linhas ≈ 2 MB.

## Decisões

**A validar com o dono (provisórias, reversíveis):** só admin/dev lançam (`mkt.pode_ver` inalterada); consumo do
número = soma de `tamanho_lista` do dia no log; projeto obrigatório em todo disparo; planilha sem `id_externo`;
edição de disparo com ferramenta desativada é recusada.

- **Ids `bigint` identity** (como `mkt.projetos`), não uuid. `p_ferramenta` é `bigint`.
- **Período em dias de São Paulo**; `p_ate` inclusivo; 366 dias no máximo (`p_ate - p_de + 1 ≤ 366`).
- **`plan_cache_mode = force_custom_plan` em `disparos_listar`**: os filtros opcionais (`v is null or col = v`) viram
  constante a cada chamada; sem isso, depois de 5 chamadas o plano genérico poderia ignorar o índice de projeto.
- **Totais do período inteiro**, numa CTE materializada (uma varredura para linhas, totais e `por_canal`). `por_canal`
  existe porque a tela soma por canal e, com 500 linhas de corte, somar no front daria total errado.
- **Validação única** (`mkt_mensageria.disparo_validar`) para a tela e para a planilha; os CHECKs da tabela ficam
  como última defesa (insert direto também é recusado).
- **CHECKs extras** não pedidos, mas que fecham buraco: `id_externo` exige `origem_sistema` (senão o único parcial não
  pega), `importacao_id` só com origem `planilha`, `arquivado_em` e `arquivado_motivo` juntos. Soma `entregues + falhas`
  em `bigint` (sem estouro de inteiro antes do CHECK).
- **DELETE e TRUNCATE recusados por trigger** nas 5 tabelas, UPDATE em `historico` e `importacoes` também (42501).
  O `drop schema … cascade` da reversão não passa por eles.
- **Chave externa só na API**: CHECK `disparos_externo_so_api` (`origem = 'api'` ou `origem_sistema`/`id_externo`
  nulos). A planilha não grava `id_externo`: não há id estável numa planilha, e a duplicata dela é tratada pela chave
  (data/hora, projeto, canal, lista) com recusa. Assim nada da planilha colide com o único `(origem_sistema, id_externo)`.
- **Procedência imutável**: além de `origem_sistema`/`id_externo`, também `origem` e `importacao_id` (mudar qualquer
  um apagaria a trilha de onde o disparo veio).
- **Ferramenta desativada / número arquivado** recusados também na **edição** de disparo antigo: para corrigir um
  disparo de ferramenta já desativada, reativar, editar e desativar (fica no histórico).
- **Nome da ferramenta único sem diferenciar maiúscula** (`lower(nome)`), porque a planilha acha a ferramenta assim.
- **Número exige `+` e país**: sem `+`, "11 99999-0000" viraria o país 1. A tela pode mascarar.
- **`capacidade_dia` pode ser nula** (não definida); a faixa 30–50 do front é aviso de tela, não regra de banco.
- **Custo de planilha até R$ 999.999,99** por disparo (cabe em `integer` de centavos com folga).
